# Лабораторные работы по компиляторам

## Лабораторная №5: массивы и строки

`lab5.py` исполняет текстовую программу в фигурных скобках. Значения бывают
числами, строками и массивами (в том числе вложенными). Поддерживаются литералы
`[1, "x", []]`, индексирование `a[0]`, присваивание `a[0] = 2`, свойство
`a.length` и `s.length`. `+` складывает числа, соединяет строки или
конкатенирует два массива, в том числе массивы строк. Смешение этих типов в
арифметике вызывает ошибку. Переменные хранят ссылки на массивы: присваивание
`b = a` не копирует массив. `==` для массивов сравнивает ссылки.

```bash
python3 lab5.py examples/lab5_list.sil --input '[1, 1, [1, 2, [1, 3, [0]]]]'
# 1; 2; 3
```

`--input` принимает последовательность JSON-значений, разделённых пробелами;
каждый `read(name)` берёт следующее значение. Строки в выводе заключаются в
кавычки, массивы выводятся в виде `[1, "x"]`. Кроме `read` и `write`, доступны
присваивание, `if`/`else`/`elif`, `while`, `do ... while`, `for` и `skip`.
Условие должно быть числом; ноль означает ложь. Выход за границы массива,
индексирование числа и изменение символа строки сообщаются как ошибки.

Прежние JSON-AST интерпретатор и стековая машина остаются в отдельных файлах.

`interpreter.py` исполняет JSON-AST напрямую. `compiler.py` переводит AST в инструкции стековой машины (SM), `machine.py` исполняет эти инструкции, а `program.py` запускает весь путь AST → SM → вывод одной командой.

```bash
python3 program.py ast.json --input 7 8
python3 compiler.py ast.json > sm.json
python3 machine.py sm.json --input 7 8
```

Вместо имени файла можно указать `-`, чтобы прочитать JSON из стандартного ввода. `read` потребляет числа из `--input` по порядку; `write` печатает их через `; `.

Проверка лабораторных:

```bash
python3 -m unittest discover -s tests
```

## Соответствие схемам с доски

`[e]` ниже означает код выражения, который оставляет результат на стеке,
а `[S]` — код оператора или блока. В исходном JSON метки сохраняются:
скомпилированную программу по-прежнему можно читать и сохранять в файл.

Полный `if (e) { S1 } else { S2 }` компилируется по схеме с первого фото:

```text
[e]
JZ L_else
[S1]
JMP L_end
LABEL L_else
[S2]
LABEL L_end
```

`while (e) { S }` соответствует схеме справа на третьем фото:

```text
LABEL L_cond
[e]
JZ L_end
[S]
JMP L_cond
LABEL L_end
```

У `do { S } while (e)` условие проверяется после тела:

```text
LABEL L_body
[S]
[e]
JNZ L_body
```

Для вложенных конструкций `new_label()` создаёт уникальные `L0`, `L1`, … .
`JZ` и `JNZ` снимают условие со стека как при выполнении перехода, так и
при продолжении со следующей команды. Ложь — 0, истина — любое ненулевое число.

## Сокращение числа шагов

1. **Метки разрешаются при загрузке.** Раньше `LABEL` оставалась в списке
   исполняемых инструкций и занимала отдельную итерацию цикла машины.
   Теперь `decode_program()` сохраняет её адрес в словаре и не добавляет
   в исполняемый список. Адрес — индекс следующей команды после удаления
   меток. Метка в конце указывает на конец программы; несколько меток
   подряд могут иметь один адрес. Повторные и отсутствующие метки остаются
   ошибками. Исходный JSON не изменяется.
2. **У `if` с `"else": "skip"` убран лишний переход.** Пустую ветку не
   нужно обходить через `JMP`, поэтому достаточно одной конечной метки:

```text
[e]
JZ L_end
[S1]
LABEL L_end
```

Условие по-прежнему вычисляется, даже если обе ветки пусты. Ошибки вычисления
и отсутствие short-circuit у `&&`/`!!` сохраняются. Полный `if/else` и схема
`while` не изменены; новые инструкции не добавлялись.

Измерения на примерах из `tests/spec_cases.json`:

| Пример | Шагов до (`f07abe2`) | Шагов после | Результат |
| --- | ---: | ---: | --- |
| №9: if без else, истинная ветка | 10 | 8 | `1` |
| №10: if/else, ложная ветка | 10 | 8 | `2` |
| №11: вложенный if (elif) | 16 | 13 | `2` |
| №12: while, три итерации | 44 | 39 | `0; 1; 2` |
| №14: do/while, три итерации | 35 | 32 | `0; 1; 2` |
| №15: do/while, одна итерация | 9 | 8 | `10` |
| №16: развёрнутый for | 44 | 39 | `0; 1; 2` |

Шаг — одна итерация исполнительного цикла VM. До изменения такая итерация
выполнялась и для `LABEL`; теперь метки вообще не попадают в этот цикл.
Загрузка JSON, компиляция и подготовка инструкций в измерение не входят.
Это сравнение числа команд, а не замер времени работы Python.

## Как показать результат

Готовый пример выполняет `x = 0; while (x < 3) { write(x); x = x + 1; }`:

```bash
python3 program.py examples/while.json --stats
```

Результат программы в stdout: `0; 1; 2`. Статистика в stderr: `Шагов: 39`.
Флаг необязателен; без него формат вывода прежний. Статистика CLI печатается
только при успешном выполнении.

Отдельная компиляция и запуск с тем же результатом:

```bash
python3 compiler.py examples/while.json > /tmp/compilers-lab-sm.json
python3 machine.py /tmp/compilers-lab-sm.json --stats
```

В Python можно передать словарь `stats` в `machine.run` или `program.run`:

```python
from program import run

stats = {}
result = run({"write": {"const": 7}}, stats=stats)
assert result == [7]
assert stats["steps"] == 2  # CONST, WRITE
```

Машина сбрасывает `stats["steps"]` при каждом запуске. В случае ошибки
исполнения словарь содержит число начатых команд, включая команду с ошибкой.

В `tests/test_control_flow.py` добавлены проверки схем с доски, вложенных
условий, меток подряд и в конце программы, потребления условия со стека,
сохранения ошибок и сокращения числа шагов. Всего в проекте 71 тестовый метод;
внутри отдельных тестов дополнительно перебираются 27 исходных примеров.
